# Quick Start

Fleet UI는 **2가지 설치 트랙(Track A / Track B)**을 제공해요.  
이 페이지에서는 “우리 팀에 맞는 트랙”을 빠르게 고를 수 있게 정리해요.

설치/설정은 [Install로 설치 시작하기](/getting-started/install)에서 단계별로 진행하면 돼요.

---

## 공통 전제(두 트랙 모두)

Fleet UI는 **react-native-unistyles** 기반이라, **Unistyles 설정**이 필요해요.
그래서 Fleet UI의 기본 테마/토큰/설정이 포함된 **`@fleet-ui/core`**를 함께 써요.

Track A는 `@fleet-ui/core`도 프로젝트 루트에 로컬로 설치해요. 그래서 필요하면 프로젝트 안에서 직접 수정할 수 있어요.

---

## 어떤 트랙을 선택해야 할까?

## 트랙 한 줄 정의

- **Track A(로컬 설치)**: CLI로 코드를 프로젝트 안으로 가져와서, “내 코드처럼” 수정/오버라이드하며 써요.(like Shadcn UI)
- **Track B(패키지 설치)**: 패키지 매니저로 설치하고, 버전 업그레이드로 업데이트해요.

## 선택은 이렇게 해요

대부분의 경우 Track A가 관리하기 용이해요. 또한 아래 질문에 답하면, 보통 1~2단계에서 결론이 나요.

1) **컴포넌트/토큰 구현을 자주 수정해야 하나요?**  
→ 네: **Track A** / 아니오: 다음 질문으로 가요.

2) **설치·업데이트·CI 안정성이 최우선인가요?**  
→ 네: **Track B** / 아니오: 다음 질문으로 가요.

3) **여러 앱/패키지가 같은 UI를 버전으로 공유해야 하나요?**  
→ 네: **Track B** / 아니오: 다음 질문으로 가요.

4) **코드를 프로젝트 안에 두고(소유권) 빠르게 실험/수정하는 흐름이 더 편한가요?**  
→ 네: **Track A** / 아니오: **Track B**를 먼저 선택해요.

---

## 빠른 선택 기준

### Track A를 추천하는 경우(로컬 설치, 소스 소유)

- **컴포넌트/토큰을 빠르게 커스터마이징**해야 해요
- 프로젝트 컨벤션에 맞게 파일 구조/스타일/동작을 직접 바꾸고 싶어요
- “SDK를 도입”한다기보다 “UI 베이스 코드를 우리 프로젝트에 가져와 관리”하는 쪽이 좋아요

### Track B를 추천하는 경우(패키지 설치)

- 토큰 오버라이딩만으로도(예: radius/shadow/colors/typography) 대부분의 스타일을 맞출 수 있어요
- 설치/업데이트/CI 안정성이 최우선이에요
- 코드 복사보다 **테마/props 조합으로 쓰는 방식**이 좋아요
- 팀이 크고 “표준 설치 → 버전업” 모델이 운영에 유리해요
