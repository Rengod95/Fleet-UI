## 공통 숙지 사항

### 1. “Entry Point” 파악

Unistyles는 앱이 시작될 때 커스텀 configuration이 있다면, 엔트리 포인트에 등록되어야 한다. 따라서 **`@fleet-ui/core/unistyles.ts`** 파일을  **엔트리 포인트**에 import 해야 한다.

**참고: [Unistyles Configuration](https://www.unistyl.es/v3/start/configuration#set-configuration)**

- **Expo Router(권장)**: 보통 `app/_layout.tsx`가 엔트리 역할을 한다.
- **react-navigation/native(권장)** 기반 프로젝트: 보통 `App.tsx` 혹은 `index.tsx`가 엔트리 역할을 한다.
- **`main.ts`** 같은 커스텀 엔트리가 있는가? → 그 파일을 엔트리로 사용한다.

> Track A의 `fleet-ui init`은 엔트리를 자동 탐지해서 import를 삽입하려고 시도한다(기본적으로 Expo Router의 `app/_layout.tsx`를 우선).

---

### 2. Track에 따라 import 경로의 alias가 다릅니다

Track A는 'local' 이라는 suffix가 붙은 alias를 사용하며, 필요하다면 이후 프로젝트 내부에서 해당 alias를 수정할 수 있도록 설계되어 있습니다.

- Track A (CLI Based Local Install)

```ts
import '@fleet-ui/local/core/unistyles';
```

- Track B (Package Manager Based Install)

```ts
import '@fleet-ui/core/unistyles';
```

---

### 3. 필수 런타임 의존성

Fleet UI는 React Native 앱에서 자주 같이 쓰이는 몇 가지 런타임 의존성을 전제로 합니다.

#### 3.1. 코어 필수(모든 트랙 공통)

아래 4개는 **거의 모든 환경에서 필요**하며, 누락 시 동작에 직접 영향을 줄 수 있습니다.

- pnpm

```bash
pnpm add react-native-unistyles react-native-reanimated react-native-gesture-handler react-native-worklets
```

- yarn

```bash
yarn add react-native-unistyles react-native-reanimated react-native-gesture-handler react-native-worklets
```

- npm

```bash
npm install react-native-unistyles react-native-reanimated react-native-gesture-handler react-native-worklets
```

- bun

```bash
bun add react-native-unistyles react-native-reanimated react-native-gesture-handler react-native-worklets
```

- Expo

```bash
npx expo install react-native-unistyles react-native-reanimated react-native-gesture-handler react-native-worklets
```

#### 3.2. 자주 필요/컴포넌트별(선택)

아래 의존성은 **컴포넌트/환경에 따라** 필요할 수 있습니다.

- (공통적으로 자주) `react-native-safe-area-context`, `react-native-svg`
- (주로 Expo 환경에서) `expo-blur`, `expo-image`, `expo-linear-gradient`

> 참고: Track A에서 `fleet-ui init`/`fleet-ui doctor`를 실행하면, 현재는 위 “선택” 의존성까지 포함해 경고가 나올 수 있습니다. 경고가 떠도 “지금 쓰는 컴포넌트에 실제로 필요한지”를 기준으로 설치하면 됩니다.

## Track A (CLI Based Local Install)

### Overview

```txt
<project-root>/
├─ app/
│  └─ _layout.tsx
├─ fleet-ui/
│  ├─ core/
│  └─ components/
└─ fleet-ui.json
```

---

### 1. init (core 설치 + alias/config 자동 세팅)

```bash
pnpm dlx @fleet-ui/cli init
```

`init`은 다음 작업을 수행합니다:

- `fleet-ui.json` 생성(경로/alias/엔트리 파일 기록)
- 엔트리에 `@fleet-ui/local/core/unistyles` import 자동 삽입
- TypeScript alias(`tsconfig.json` paths) 설정
- Babel alias(`module-resolver`) 설정
- Unistyles plugin의 `autoProcessImports` 정합
- 필수/개발 의존성 누락 시 설치 커맨드 안내

옵션(필요할 때):

```bash
# 예: 다른 프로젝트 루트에서 실행할 때
pnpm dlx @fleet-ui/cli init --cwd ./apps/my-app

# 예: 설치 경로를 바꾸고 싶을 때
pnpm dlx @fleet-ui/cli init --core-dir src/fleet-ui/core --components-dir src/fleet-ui/components

# 예: alias prefix를 바꾸고 싶을 때
pnpm dlx @fleet-ui/cli init --alias @fleet-ui/local
```

---

### 2. init 이후 “정상 상태” 확인

#### 2.1. 엔트리 import가 들어갔는지

Expo Router 기준:

```ts
// app/_layout.tsx
import '@fleet-ui/local/core/unistyles';
```

#### 2.2. TypeScript paths(alias)가 들어갔는지

`tsconfig.json` (개념 예시):

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@fleet-ui/local/*": ["fleet-ui/*"]
    }
  }
}
```

> 이 설정은 **타입/에디터**를 위한 것이고, 런타임(Metro/Babel)도 별도로 맞춰줘야 한다.

#### 2.3. Babel 설정이 맞는지(런타임 alias + reanimated + unistyles)

`babel.config.js`(또는 `babel.config.cjs`)에서 핵심은 3가지다.

1) `module-resolver`로 alias를 런타임에서 해석
2) `react-native-unistyles/plugin`의 `autoProcessImports`에 `@fleet-ui/local` 포함
3) **`react-native-reanimated/plugin`은 plugins 배열의 마지막**

개념 예시:

```js
module.exports = function (api) {
  api.cache(true);
  return {
    presets: ['babel-preset-expo'],
    plugins: [
      [
        'module-resolver',
        {
          alias: {
            '@fleet-ui/local': './fleet-ui',
          },
        },
      ],
      ['react-native-unistyles/plugin', { autoProcessImports: ['@fleet-ui/local'] }],
      'react-native-reanimated/plugin',
    ],
  };
};
```

> Track A에서는 `init`이 이 설정을 best-effort로 패치한다.

### 3. 컴포넌트 추가

필요한 컴포넌트만 골라서 가져온다.

```bash
pnpm dlx @fleet-ui/cli add Button Modal
```

`add`가 하는 일(요약):

- registry에서 컴포넌트 소스 복사
- 내부 import를 best-effort로 `@fleet-ui/local/core` 기준으로 맞춤
- 대상 디렉터리의 `index.ts`(barrel) 업데이트

---

### 4. 컴포넌트별 선택 의존성(자주 쓰는 예시)

아래는 “이 컴포넌트를 쓰면 추가로 필요해질 수 있는 deps”의 대표 예시다.

| 컴포넌트 | 필요할 수 있는 의존성 |
| --- | --- |
| `Modal`, `ImageCard` | `expo-blur` |
| `IconButton`, `ImageCard` | `expo-image` |
| `Swiper`, `ImageCard` | `expo-linear-gradient` |
| (공통적으로 자주) | `react-native-safe-area-context`, `react-native-svg` |

설치 예시(Expo 권장):

```bash
npx expo install expo-blur expo-image expo-linear-gradient react-native-safe-area-context react-native-svg
```

> 참고: expo package에 대한 종속성을 제거하고 싶은 경우, CLI를 통한 컴포넌트 추가 시 선택적으로 해당 의존성을 대체할 수 있습니다.

---

### 5. doctor(권장)

```bash
pnpm dlx @fleet-ui/cli doctor
```

`doctor`가 주로 확인하는 것:

- `fleet-ui.json` 존재
- 엔트리 import 존재
- tsconfig alias 존재
- babel alias + unistyles autoProcessImports 존재
- 필수/개발 의존성 누락

## Track B (NPM package install)

> 목표: 설치/업데이트 안정성을 최우선으로 두고, 패키지 버전 업그레이드로 변경을 흡수한다.

### 1. 패키지 설치

```bash
pnpm add @fleet-ui/core @fleet-ui/components
```

### 2. 엔트리 import 추가(강제)

```ts
import '@fleet-ui/core/unistyles';
```

### 3. peerDependencies 설치(필수)

패키지 트랙에서는 런타임 의존성이 peerDependencies로 선언되므로, 앱에서 직접 설치해야 한다.

```bash
pnpm add react-native-unistyles react-native-reanimated react-native-gesture-handler react-native-worklets
pnpm add react-native-safe-area-context react-native-svg
```

Expo 기반 기능을 쓰는 컴포넌트(Blur/Image/Gradient 등)를 사용한다면:

```bash
pnpm add expo-blur expo-image expo-linear-gradient
```

> Expo 프로젝트에서는 `pnpm add` 대신 `npx expo install`을 권장한다.

---

### 4. Babel 설정 체크(특히 Reanimated)

패키지 트랙이라고 해서 Reanimated 설정이 자동으로 끝나진 않는다.

- `babel.config.js`에 `react-native-reanimated/plugin`이 필요할 수 있다
- **plugins 배열의 마지막**이어야 한다

최소 예시:

```js
module.exports = function (api) {
  api.cache(true);
  return {
    presets: ['babel-preset-expo'],
    plugins: ['react-native-reanimated/plugin'],
  };
};
```

이미 다른 plugins가 있다면:

```js
plugins: [
  // ...기존 plugins...
  'react-native-reanimated/plugin',
]
```

## Troubleshooting (자주 하는 실수 체크리스트)

### 1) “unistyles가 적용되지 않음 / 테마가 안 먹음”

- 엔트리 파일에 import가 있는지 확인
  - Track A: `@fleet-ui/local/core/unistyles`
  - Track B: `@fleet-ui/core/unistyles`

### 2) “@fleet-ui/local/* 모듈을 찾을 수 없음”(Track A)

- `tsconfig.json`의 `paths`가 잡혀있는지 확인
- `babel.config.js`에 `module-resolver` alias가 있는지 확인
- `react-native-unistyles/plugin`의 `autoProcessImports`에 `@fleet-ui/local`이 포함되어 있는지 확인

### 3) “Reanimated 관련 에러 / 앱이 바로 크래시”

- `babel.config.js`에 `react-native-reanimated/plugin`이 있는지 확인
- **plugins 배열의 마지막인지 확인**

### 4) “특정 expo 모듈(expo-blur/expo-image/expo-linear-gradient)을 찾을 수 없음”

- 그 컴포넌트가 실제로 해당 의존성을 쓰는지 확인(위 표 참고)
- Expo라면 `npx expo install <dep>`로 버전 정합 설치 권장
